01

Qué es Brain

Brain no es una libreta: es el disco de arranque de la identidad digital. Vive en un disco externo (D:\Brain en Windows, /mnt/d/Brain en WSL), viaja entre PCs y es la única pieza que Hermes necesita para reconstruirse.

Las tres capas (vault-assisted-workflow)

Captura         →  00-inbox/ (ideas) · 00-raw/ (fuentes inmutables) · #inbox de Discord
Procesamiento   →  Hermes + skills: busca contexto, investiga, trabaja, documenta
Conocimiento    →  01-knowledge/ · 02-projects/ · 04-skills/ · index.md · git

El principio rector está en 03-identity/hermes.md: el vault es la fuente de verdad; se prefiere información existente antes que inventar, y toda respuesta sustancial se documenta.

“El conocimiento se guarda SIEMPRE en el vault, no en la memoria interna del agente — el vault viaja en el disco D:, la memoria no.” — 03-identity/user.md

03

Convenciones que sostienen todo

SCHEMA.md define el contrato de la bóveda:

Frontmatter

Metadatos obligatorios

title, created, updated, type (concept / entity / comparison / project / log / raw / identity), tags, confidence opcional y sources opcional.

Taxonomía

Tags por familias

Tecnología, herramientas/ecosistema, dominio intelectual y meta. Nada de tags inventados por nota.

Grafo

Mínimo 2 wikilinks

Cada nota de conocimiento enlaza al menos con dos notas; al editar se actualiza updated:.

Inmutabilidad

00-raw no se toca

Las fuentes originales nunca se modifican. El procesado se marca con un sidecar .meta.yaml.

Umbral

Cuándo crear página

Solo si el tema es central o aparece en 2+ fuentes; si ya existe, se añade; se divide a partir de ~200 líneas.

Nombres

Minúsculas con guiones

llm-agents.md, nunca LLM Agents.md. .gitattributes fuerza LF y marca binarios; .gitignore excluye JARs, ZIPs, ISO, binarios de Minecraft y vídeos/imágenes de reels.

Workflow real con Hermes

4.1 · Stack de ejecución

Windows 11
└── WezTerm (Tokyo Night, FiraCode Nerd Font, opacidad 0.92, WSL por defecto)
    └── WSL2 Ubuntu (systemd=true, usuario javier)
        ├── Hermes Agent en ~/.hermes/
        │   ├── config.yaml      (modelo, toolsets, memoria, cron…)
        │   ├── .env             (API keys y tokens)
        │   ├── skills/          (183 activas, 26 categorías)
        │   ├── scripts/         (brain-scan.py, brain-extract.py)
        │   ├── cron/jobs.json   (brain-raw-ingest)
        │   ├── memories/        (MEMORY.md + USER.md)
        │   ├── SOUL.md          (personalidad: "Hermes")
        │   └── kanban.db, sessions/
        ├── hermes-gateway.service (systemd --user, linger activo)
        └── /mnt/d/Brain         (el vault)

Modelo y proveedor: deepseek-v4-flash vía opencode-go (https://opencode.ai/zen/go/v1, modo chat_completions), ~10 $/mes. config.yaml fija 90 turnos máximos, timeouts de gateway de 1.800 s, compresión de contexto al 50 % con ratio 0,2 y protección de los últimos 20 mensajes.

4.2 · Protocolo de arranque de cada sesión

Documentado en hermes-complete-guide.md; es literalmente lo primero que hace Hermes:

  1. Verificar que /mnt/d/Brain está montado — si no, avisa antes de nada.
  2. Leer 03-identity/user.md — contexto completo del usuario.
  3. Consultar index.md — qué existe ya, para no duplicar.
  4. Buscar en orden: 03-identity → 02-projects → 01-knowledge → 00-inbox.

4.3 · Protocolo obligatorio al terminar (9 pasos)

  1. Fuentes externas → 00-raw/articles/ o 00-raw/papers/
  2. Conceptos nuevos → 01-knowledge/concepts/
  3. Entidades nuevas → 01-knowledge/entities/
  4. Comparativas → 01-knowledge/comparisons/
  5. Si toca un proyecto → actualizar 02-projects/
  6. Si aprendió algo del usuario → actualizar 03-identity/user.md
  7. Entrada en 05-logs/YYYY-MM-log.md
  8. Añadir las notas nuevas a index.md
  9. git add -A && git commit -m "session: …"
Consecuencia práctica: una sesión de chat no se pierde. El log de octubre documenta decisiones, bugs, lecciones y pendientes del despliegue on-demand con un nivel de detalle que un chat normal jamás conservaría.

5.2 · Pipeline de ingestión automática

Dejas un archivo en 00-raw/  (o lo mandas a #inbox)
        ↓
cron brain-raw-ingest  (cada 60 min, --no-agent, deliver local)
        ↓
brain-scan.py  → detecta archivos SIN sidecar .meta.yaml
                 clasifica image/pdf/text/binary, calcula sha256 de cabecera
        ↓
skill brain-vault/raw-ingest
   PDF   → brain-extract.py (pymupdf, página a página)
   Imagen→ vision tool
   Texto → lectura directa (utf-8 / latin-1 / utf-16)
        ↓
notas atómicas en 01-knowledge/ + sidecar [archivo].meta.yaml
        ↓
nunca se reprocesa
  • 143 sidecars ya generados en 00-raw/.
  • El sidecar es el marcador de “procesado”; el escaneo ignora .meta.yaml, ocultos y basura del sistema.
  • Tirith bloquea el cron si el prompt ensamblado contiene patrones destructivos (rm -rf /…) — incluso dentro de bloques de código markdown. Eso mantuvo el cron muerto desde el 9 de mayo hasta que se documentó y se reescribió la skill.
  • Test manual: python3 ~/.hermes/scripts/brain-scan.py.

5.3 · Bot de Discord del servidor Losy

Independiente de Hermes. Python + discord.py en el portátil-servidor (piano@192.168.0.5, systemd discord-bot.service), hablando con Minecraft por RCON en 127.0.0.1:25575.

Chat y avisos

Minecraft ↔ Discord

  • Chat bidireccional (filtra /, limpia prefijos de rango FTB)
  • Embeds de conexión/desconexión, logros, muertes y estado
  • Convención de colores: verde/rojo = estado, azul/gris = jugadores, naranja/cian = backups, amarillo = logros, morado = muertes
Comandos

Slash commands

  • /online, /status (TPS vía Spark, RAM y uptime de /proc)
  • /anunciar, /whitelist, /start, /close
  • Whitelist por reacción ✅ con toggle: quitar la reacción revoca, expulsa del juego y retira el rol
Ciclo de vida

Modo on-demand (27/10)

  • El Java no arranca al boot; /start lo levanta (3-6 min con 468 mods)
  • /close: cuenta atrás de 60 s dentro del juego, save-all, stop graceful y fallback a systemctl stop
  • Auto-cierre por inactividad a los 30 min con 0 jugadores, aviso ⏲️
Robustez

Vigilante y permisos

  • Vigilante de estado cada 30 s, solo emite en cambio real (lock antiduplicados), se sincroniza sin emitir al arrancar
  • Lector de log tolerante a 2/3/4 prefijos [...] — antes descartaba joins en silencio
  • /start y /close solo rol Minecraft Verificado + canal #mc-info; sudoers NOPASSWD limitado a systemctl start|stop minecraft

Backup diario · 9:00

Doble modo

Servidor arriba: aviso en juego, parada graceful, tar --zstd de world + config + server.properties, rearranque.

Servidor parado: copia offline silenciosa, sin tocar servicios.

Rotación a 2 copias, limpieza de logs >7 días y crash-reports >30 días, flag /tmp/mc-backup-running con trap de limpieza, embeds 💾/✅ por webhook. Hooks: aviso-inicio deshabilitado (mentía con el Done viejo del log), aviso-apagado se mantiene (el 🔴 real al apagar el portátil). bootfix-losy.sh y desplegar-losy.sh cubren diagnóstico, limpieza de Wants/Requires, visudo -c y checklist post-deploy.

06

Calidad de vida construida

En Hermes

Bootstrap de un comando

Reconstruye todo el entorno en un PC nuevo: detecta el vault, configura WSL, PATH y dependencias, instala Hermes, restaura config.yaml (con backup), crea .env interactivo pidiendo cada key con explicación de dónde sacarla, copia skills y scripts, crea el cron y ejecuta hermes doctor --fix. El .ps1 instala además WSL, WezTerm y 18 variantes de FiraCode.

En Hermes

Idempotencia

No sobreescribe config, no re-pide keys ya puestas y verifica 0 errores al final. Repetir el bootstrap no rompe nada.

En Hermes

Contexto domado

Memoria con límites de caracteres (no se infla), compresión automática, curator que archiva skills muertas, checkpoints, guardrails de tool-loop con avisos y parada dura.

En Hermes

Sesiones y voz

Sesiones buscables (session_search), logs de trayectoria, TTS/STT y personalidades múltiples.

En el vault

Índice y auditoría

  • index.md como catálogo maestro con resumen de una línea por página — evita duplicados
  • vault-health: wikilinks rotos, huérfanos, ghost artifacts y conteos desfasados
  • vault-concept-splitting: no crear monolitos
  • vault-document-decisions: lo no documentado se considera trabajo perdido
En el vault

Captura y memoria

  • Logs con decisión, motivación, verificación, bugs, lecciones, pendientes y “cómo volver atrás”
  • 00-inbox como buffer sin fricción y #inbox de Discord como entrada desde el móvil sin gastar tokens
  • .gitignore/.gitattributes afinados para no inflar el repo ni romper entre Windows y WSL
  • Pitfalls reales documentados: IDs de canal, Tirith, UnboundLocalError en on_ready, sync de comandos, WiFi vs servidor, cookies de Instagram
07

Frágil o pendiente

01

Secretos dentro del repo

hermes-bootstrap/.env.template contiene una API key y un token de Discord reales; 00-inbox/backup.sh lleva la contraseña de RCON en claro; instagram-cookies.txt está en la raíz; y 02-projects/moodle-scraper/.env aparece trackeado en git status.

→ Están en el historial de git: rotarlos es más urgente que borrarlos.
02

El espejo de skills está desfasado

04-skills/system/ tiene 112 skills frente a las 183 reales (faltan 115, sobran 44). 04-skills/index.md todavía habla de 110.

→ La fuente de verdad es ~/.hermes/skills, no el vault. Falta un rsync automático.
03

No hay remoto de git

430 commits viven solo en el disco externo: si ese disco muere, se pierde el historial (el markdown sigue ahí, pero sin versiones).

→ Añadir remoto privado y push periódico desde el cron.
04

El índice miente en los números

Declara 6.943 páginas, hay ~6.900 ficheros en total, y arrastra líneas corruptas (||, |-) y enlaces a notas que ya no existen.

→ Pasar vault-health con más frecuencia y regenerar conteos.
05

Parche del inbox y hooks manuales

Tras reinstalar, el bootstrap no restaura el parche de discord.py ni los hooks aviso-*. Es el punto donde una migración “funciona” pero pierde una función silenciosa.

→ Incluirlos en el bootstrap o en un script de post-instalación.
06

Puertos abiertos a la LAN

RCON y 25565 estaban abiertos a la LAN (22/25565/25575) según el log del 27/10; el firewall quedó pendiente.

→ ufw cerrando 25565/25575 a la LAN manteniendo 22/SSH.
07

Cookies de Instagram caducas

Caducan en ~48 h y el pipeline falla en silencio; la propia nota de cuentas de plataforma lo identifica como el freno real.

→ Alerta explícita (Discord) cuando el worker falla por sesión caducada.
08

Ruido en la raíz

Sin título.canvas vacío y el JSON de n8n suelto en la raíz rompen la convención de nombres del propio SCHEMA.md.

→ Mover el JSON a 02-projects/ y borrar el canvas vacío.
08

Resumen en una frase

Tienes un sistema operativo personal, no una bóveda de notas: captura sin fricción, un agente que lee tu perfil antes de responder, un cron que convierte 00-raw en conocimiento atómico cada hora, documentación obligatoria con commit, y una capa de automatizaciones reales (Discord, Minecraft on-demand con backups, n8n, Spotify, Moodle) gobernada desde un disco que viaja contigo.

Lo que le falta para ser sólido no es más funcionalidad: es sacar los secretos del repo, ponerle remoto a git y automatizar la resincronización de skills.
